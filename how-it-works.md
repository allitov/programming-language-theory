# Как это работает: конечные автоматы и их минимизация

Лабораторная работа: на вход программа получает **НКА** (недетерминированный конечный автомат),
на выходе — **минимизированный ДКА**. Реализация на Java, сборка Gradle, тесты JUnit 5 + AssertJ.

---

## 1. Краткая теория

### 1.1. Конечные автоматы

Конечный автомат — пятёрка **A = (S, Σ, δ, s₀, F)**, где:

- **S** — конечное множество состояний;
- **Σ** — входной алфавит (конечное множество символов);
- **δ** — функция переходов;
- **s₀ ∈ S** — начальное состояние;
- **F ⊆ S** — множество заключительных (допускающих) состояний.

Автомат читает слово — конечную строку символов алфавита — символ за символом, двигаясь по
переходам. Если после прочтения всего слова хотя бы одна ветка работы закончилась в состоянии
из `F`, слово **допускается**; множество всех допускаемых слов — **язык** автомата `L(A)`.

Различают три вида автоматов:

| Вид       | Переходы              | Детерминированность                                                |
|-----------|-----------------------|--------------------------------------------------------------------|
| **ДКА**   | `δ: S × Σ → S`        | из каждого состояния по каждому символу — не более одного перехода |
| **НКА**   | `δ: S × Σ → P(S)`     | допустимо несколько (и ноль) переходов по одному символу           |
| **ε-НКА** | + `δ: S × {ε} → P(S)` | допустимы ε-переходы, не потребляющие входных символов             |

ДКА — частный случай НКА, поэтому любая программа, работающая с НКА, работает и с ДКА.

### 1.2. Проверка на детерминированность

Автомат детерминирован, когда:

1. у него **нет ε-переходов** (переход «впустую» ломает однозначность шага);
2. для каждой пары *(состояние, символ)* есть **не более одного** целевого состояния.

Отсутствующие переходы допустимы — такой автомат называют *частичным ДКА*, он остаётся
детерминированным. Проверка тривиальна (два прохода по таблице переходов), но именно она
решает, понадобится ли этап детерминизации.

### 1.3. Детерминизация: построение подмножеств (теорема Рабина — Скотта)

НКА и ДКА эквивалентны по выразительной силе: для любого НКА существует ДКА, распознающий
тот же язык. Классическое доказательство конструктивно — **метод построения подмножеств**
(powerset construction):

- состоянием ДКА объявляется **множество состояний НКА**, которые могут быть активны
  одновременно; интуитивно ДКА «отслеживает все ветки работы НКА параллельно»;
- переход по символу `a`: из подмножества `T` берём все цели `δ(s, a)` для каждого `s ∈ T`;
- чтобы убрать ε-переходы, до и после каждого шага берётся **ε-замыкание** — множество всех
  состояний, достижимых из данных по ε-переходам (включая сами исходные состояния);
- подмножество допускающее, если содержит хотя бы одно допускающее состояние НКА.

В худшем случае ДКА получает до `2ⁿ` состояний (экспонента по числу состояний НКА), но на
практике из множества достижимых обычно выживает лишь малая часть.

### 1.4. Минимизация: эквивалентность состояний

Ключевое понятие — **эквивалентность состояний**: состояния `p` и `q` эквивалентны
(`p ≡ q`), если для любого слова `w` автомат, запущенный из `p`, допускает `w` тогда и только
тогда, когда запущенный из `q`. Эквивалентные состояния неразличимы извне, и их можно
склеить, не изменив язык. Это отношение — конгруэнция: если `p ≡ q`, то для любого символа
`a` их преемники тоже эквивалентны (`δ(p,a) ≡ δ(q,a)`).

**Теорема Майхилла — Нерода** даёт критерий: два состояния различимы тогда и только тогда,
когда существует слово, приводящее одно из них в допускающее состояние, а другое — в
нетерпящее. Минимальный ДКА для регулярного языка существует и единственен с точностью до
переименования состояний.

**Алгоритм уточнения разбиения (алгоритм Мура)** — итеративное «грубое» разбиение:

1. **Удалить недостижимые состояния** — они не влияют на язык.
2. **Начальное разбиение**: `Π₀ = {F, S ∖ F}` — допускающие и нетерпящие состояния различимы
   уже пустым словом.
3. **Уточнение**: на каждом шаге состояние получает *сигнатуру* — пару
   «(номер его класса; номера классов, в которые ведут переходы по каждому символу, или
   пометка „перехода нет“)». Состояния с разными сигнатурами различимы и разбиваются на
   разные классы. Шаги повторяются, пока число классов растёт; когда разбиение перестало
   меняться, каждый класс — один класс эквивалентности.
4. **Построить автомат классов**: состояния — классы, переходы — между классами, начальный
   класс содержит `s₀`, допускающие классы содержат `F`.

Словами длины ≤ *k* состояния различимы ровно после *k* итераций, поэтому по стабилизации
все классы — полные классы эквивалентности, и результат минимален. Сложность — `O(n² · |Σ|`
итерационных сравнений; для промышленных применений используют алгоритм Хопкрофта
(`O(n log n)`), здесь выбран Мур ради наглядности.

> **Почему «перехода нет» — отдельная метка.** Для частичного ДКА отсутствие перехода —
> такое же поведение, как любой другой: два состояния, у которых переходы отсутствуют на
> одних и тех же символах, эквивалентны. Если бы вместо метки мы добавляли «ловушку»
> (сток), минимальный частичный ДКА искусственно оброс бы лишним состоянием. В этой
> реализации недостающий переход в сигнатуре кодируется значением `-1`.

## 2. Формат входных данных

Текстовый, построчный; `#` и `//` — комментарии, пустые строки игнорируются:

```
# НКА: слова над {0, 1}, оканчивающиеся на "01"
states: q0 q1 q2        # все состояния
alphabet: 0 1           # алфавит
start: q0               # ровно одно начальное состояние
final: q2               # допускающие состояния (ключи final/finals)

transitions:            # дальше — по одному переходу в строке
q0 0 q0 q1              # из q0 по 0 — в q0 И в q1 (недетерминизм)
q0 1 q0
q1 1 q2
q1 eps q0               # eps (или буква ε) — ε-переход
```

- Недетерминизм выражается естественно: несколько целей в одной строке перехода.
- Ошибки (неизвестное состояние/символ, дублирование секции, «мусор» вне секций) сообщаются
  с номером строки: `line 6: unknown state 'q7'`.

## 3. Логика программы

### 3.1. Конвейер

```
строка ──► AutomatonParser ──► FiniteAutomaton (НКА)
                                   │
                     DeterminismChecker.check()
                                   │
                    ┌──────────────┴──────────────┐
              детерминирован                 недетерминирован
                    │                              │
                    │                    Determinizer.determinize()
                    │                    (построение подмножеств + ε-замыкания)
                    └──────────────┬──────────────┘
                                   ▼
                          FiniteAutomaton (ДКА)
                                   │
                        Minimizer.minimize()
                     (недостижимые ↓, разбиение на классы)
                                   ▼
                        MinimizationResult.minimized
```

Фасад `AutomatonMinimizer.minimize()` возвращает `MinimizationResult`: исходный автомат,
вердикт проверки с перечнем нарушений, промежуточный ДКА (тот же объект, если вход уже был
ДКА) и итоговый минимальный ДКА.

### 3.2. Классы

| Класс                                                 | Ответственность                                                                                                                                                                 |
|-------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `automaton.Transition`                                | record `(from, symbol, to)` — один переход                                                                                                                                      |
| `automaton.FiniteAutomaton`                           | неизменяемая модель; конструктор проверяет все инварианты; хранит переходы и индекс `состояние → символ → цели`; умеет вычислять ε-замыкание и моделировать распознавание слова |
| `automaton.DeterminismChecker`                        | проверка на детерминированность, возвращает `DeterminismReport` со списком нарушений                                                                                            |
| `automaton.Determinizer`                              | детерминизация построением подмножеств; состояние-подмножество из одного элемента сохраняет исходное имя, из нескольких — получает имя `{q0,q1,q2}`                             |
| `automaton.Minimizer`                                 | удаление недостижимых состояний + уточнение разбиения; принимает только ДКА (иначе `IllegalArgumentException`)                                                                  |
| `automaton.AutomatonMinimizer` / `MinimizationResult` | фасад всего конвейера и его результат                                                                                                                                           |
| `automaton.AutomatonParser`                           | парсер текстового формата с диагностикой по номерам строк                                                                                                                       |
| `automaton.AutomatonPrinter`                          | печать автомата обратно в текстовый формат (результат можно скормить программе снова) и экспорт в Graphviz DOT                                                                  |
| `exception.AutomatonFormatException`                  | ошибка формата входных данных                                                                                                                                                   |
| `Main`                                                | чтение из файла-аргумента или stdin, запуск конвейера, печать отчёта                                                                                                            |

Модель неизменяема и самопроверяема: невозможно создать автомат с переходом в
необъявленное состояние, символом вне алфавита или ε в алфавите — все инварианты
проверяются в конструкторе.

### 3.3. Ключевые фрагменты

**ε-замыкание** — обход в глубину по ε-переходам (`FiniteAutomaton#epsilonClosure`):

```java
Set<String> closure = new LinkedHashSet<>(source);
Deque<String> pending = new ArrayDeque<>(closure);
while (!pending.isEmpty()) {
    for (String target : targets(pending.pop(), EPSILON)) {
        if (closure.add(target)) {          // add возвращает true только для нового состояния
            pending.push(target);
        }
    }
}
```

**Распознавание слова НКА** — «текущее состояние» это множество веток; на каждом символе
множество целиком переехало по переходам и замкнуло ε (`FiniteAutomaton#accepts`):

```java
Set<String> current = epsilonClosure(Set.of(start));
for (String symbol : symbols) {
    Set<String> next = new LinkedHashSet<>();
    for (String state : current) next.addAll(targets(state, symbol));
    current = next.isEmpty() ? Set.of() : epsilonClosure(next);
}
return !Collections.disjoint(current, finals);
```

**Детерминизация** (`Determinizer#determinize`) — обход в ширину по подмножествам, начиная
с ε-замыкания начального состояния; непустые преемники получают имя и ставятся в очередь.
Частичный ДКА получается естественно: пустое множество преемников просто не порождает
переход.

**Минимизация** (`Minimizer#minimize`) — цикл уточнения разбиения:

```java
while (true) {
    Map<List<Integer>, Integer> classBySignature = new LinkedHashMap<>();
    Map<String, Integer> refined = new LinkedHashMap<>();
    for (String state : reachable) {
        List<Integer> signature = new ArrayList<>();
        signature.add(classes.get(state));                    // собственный класс
        for (String symbol : alphabet) {
            Set<String> targets = automaton.targets(state, symbol);
            signature.add(targets.isEmpty() ? NO_TARGET : classes.get(targets.iterator().next()));
        }
        refined.put(state, classBySignature.computeIfAbsent(signature, key -> classBySignature.size()));
    }
    boolean stable = classBySignature.size() == distinctClasses(classes);
    classes = refined;
    if (stable) break;
}
```

Сигнатура — список целых (для детерминированного автомата у пары *(состояние, символ)* не
больше одной цели; `-1` = перехода нет). Пока число классов растёт — уточняем; стабилизация
означает, что получено разбиение на классы эквивалентности. Имена классам даются по тому же
правилу, что и подмножествам: одиночка сохраняет имя состояния, склейка зовётся `{q2,q3}`.

### 3.4. Примеры работы

НКА «слова, оканчивающиеся на 01» (`examples/ends-with-01.txt`):

```
Deterministic: no
  ! state 'q0' has 2 transitions on symbol '0'

After subset construction:
states: q0 {q0,q1} {q0,q2}
alphabet: 0 1
start: q0
final: {q0,q2}
transitions:
q0 0 {q0,q1}
q0 1 q0
{q0,q1} 0 {q0,q1}
{q0,q1} 1 {q0,q2}
{q0,q2} 0 {q0,q1}
{q0,q2} 1 q0

Minimal DFA (states: 3 -> 3)
```

Проследим построение подмножеств: `q0` --0--> {q0,q1} (по 0 из q0 идём и в q0, и в q1);
{q0,q1} --1--> {q0,q2} — накопили «хвост 1», и среди активных состояний есть допускающее q2.
Полученный ДКА уже минимален (3 состояния), минимизация не находит склеек.

ДКА со склейкой (`examples/merge-equivalent.txt`, `4 -> 3`):

- `Π₀ = { {q0,q1} , {q2,q3} }` — допускающие против остальных;
- итерация 1: сигнатуры `q0 = (0; 0, 0)`, `q1 = (0; 1, 0)`, `q2 = (1; 1, 1)`,
  `q3 = (1; 1, 1)` → разбиение `{ {q0}, {q1}, {q2,q3} }` (q1 попал по «a» в допускающий
  класс, q0 — нет; q2 и q3 неразличимы);
- итерация 2: классов по-прежнему 3 — разбиение стабилизировалось, `q2 ≡ q3`, что и видно в
  выводе: `Minimal DFA (states: 4 -> 3)`, состояние `{q2,q3}`.

## 4. Запуск

```bash
# из файла (JDK 25 подтягивается toolchain-ом Gradle автоматически)
./gradlew run --args="examples/ends-with-01.txt"

# или из stdin — собрать дистрибутив и запустить стартовый скрипт
./gradlew installDist
build/install/plt/bin/plt < examples/ends-with-01.txt     # Windows: plt.bat

# тесты
./gradlew test
```

> Стартовый скрипт дистрибутива использует `java` из PATH, поэтому для него нужен
> JDK 25 (классы скомпилированы под class file 69). Gradle-задача `run` такого требования
> не предъявляет — она использует тулчейн.

Программа печатает: входной автомат, вердикт проверки (при недетерминизме — причины),
промежуточный ДКА (если нужна была детерминизация), минимальный ДКА и сокращение числа
состояний. Ошибки входных данных выводятся в stderr с кодом возврата 1.

## 5. Тесты

Корректность проверяется двумя способами:

1. **точные ожидания** — для ручных примеров зафиксированы состояния, финалы, переходы и
   имена склеенных классов;
2. **перебор языков** (`Languages.assertEquivalent`) — сильный приём для проверки
   эквивалентности автоматов: перебираются все слова алфавита до заданной длины (для
   {0,1} и длины 6 — 127 слов) и утверждается совпадение ответов «допустить/отклонить» у
   исходного НКА и результата. Это свойственная автоматам проверка: язык — единственное
   наблюдаемое поведение.

| Тестовый класс           | Что покрывает                                                                                                                                                     |
|--------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `FiniteAutomatonTest`    | инварианты модели, ε-замыкание, семантика допуска НКА (любая ветка), пустое слово                                                                                 |
| `DeterminismCheckerTest` | ДКА/частичный ДКА — детерминированы; несколько переходов по символу и ε-переход — нарушения                                                                       |
| `DeterminizerTest`       | ДКА проходит через детерминизацию без изменений; НКА → эквивалентный ДКА (перебор слов); ε-переходы поглощаются замыканиями                                       |
| `MinimizerTest`          | удаление недостижимых, склейка эквивалентных, уже минимальный не меняется, коллапс всех допускающих, частичный ДКА остаётся частичным (без ловушек), отказ на НКА |
| `AutomatonParserTest`    | полный разбор, ε-псевдонимы, ошибки с номерами строк, дубликаты секций                                                                                            |
| `AutomatonPrinterTest`   | круглый путь «напечатать → распарсить → равный автомат», экспорт DOT                                                                                              |
| `AutomatonMinimizerTest` | сквозной конвейер НКА → минимальный ДКА с сохранением языка; детерминированный вход не детерминизируется повторно                                                 |
| `MainTest`               | текст отчёта для НКА и ДКА, отказ на ломаном входе                                                                                                                |
