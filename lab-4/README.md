# Лабораторная работа № 4 — универсальный МП-преобразователь (перевод в ОПЗ)

Программа — **универсальный МП-преобразователь**: конфигурация и правила переходов `δ` не «зашиты»
в код, а читаются из json-файла; выражения поступают из консольного ввода; каждый такт
`(q, x, α, y) ⊢ (q', x', α', y')` печатается в консоль и логируется (`@Slf4j`).

Формальная часть (КС-грамматика, простая СУ-схема, спецификация преобразователя, разбор контрольного
примера) — в [rules.md](rules.md). Конфигурация ОПЗ-преобразователя — [transducer.json](transducer.json).

## Запуск

```text
gradlew.bat :lab-4:run --args="transducer.json"
```

- путь к json передаётся аргументом программы (относительный путь отсчитывается от каталога модуля
  `lab-4`, можно указать абсолютный);
- если аргумент не задан, программа попросит ввести путь;
- **завершение сеанса**: пустая строка или команда `exit` (регистр не важен);
- ошибка при обработке одной строки (недопустимый символ, нарушение синтаксиса и т. п.) печатает
  диагностику с позицией и **не завершает** работу программы.

Требования: Java 25 (toolchain), Gradle wrapper включён. Сборка — `gradlew.bat build`,
тесты — `gradlew.bat :lab-4:test`.

## Формат json-конфигурации

| Поле | Компонент | Описание |
|------|-----------|----------|
| `states` | `Q` | непустой список состояний (`q0, q1 …`) |
| `inputAlphabet` | `V` | входной алфавит (символы `λ` и `ε` объявлять нельзя — они обозначают пустую цепочку) |
| `stackAlphabet` | `Z` | алфавит магазина; символы могут быть многосимвольными (`"(0"`) |
| `outputAlphabet` | `V'` | выходной алфавит; может содержать пробел `" "` — разделитель лексем |
| `startState` | `q₀` | начальное состояние, обязан входить в `states` |
| `startStackSymbol` | `z₀` | начальный символ магазина, обязан входить в `stackAlphabet` |
| `finalStates` | `F` | заключительные состояния, каждое обязано входить в `states` |
| `transitions` | `δ` | список правил; каждый элемент: |

Поля правила:

| Поле | Символ | Описание |
|------|--------|----------|
| `state` | `q` | исходное состояние |
| `input` | `a` | входной символ или `"λ"` (λ-переход) |
| `stackTop` | `z` | символ на вершине магазина |
| `newState` | `r` | новое состояние |
| `push` | `α` | цепочка, заменяющая `z` в магазине; записывается **с вершины** (`"(0Z"`: вершина — `(0`); `"λ"` — удалить символ; тот же символ — не менять магазин |
| `output` | `t` | цепочка, выдаваемая на выходную ленту; `"λ"` — ничего не выдавать; символ `num` означает «текст прочитанной лексемы-числа» (эхо входа) |

Правило в целом: `δ(q, a, z) = (r, α, t)`.

Проверяемые требования к конфигурации (нарушение — ошибка `ConfigurationException` с сообщением):

- все обязательные поля присутствуют;
- `startState` и элементы `finalStates` принадлежат `states`, `startStackSymbol` — алфавиту магазина;
- символы в правилах принадлежат заявленным алфавитам (для `push` и `output` цепочки разбиваются на
  атомарные символы по наибольшему совпадению);
- **детерминированность**: для каждой тройки `(q, a, z)` существует не более одного правила; λ-правило
  для пары `(q, z)` допускается только при отсутствии правил по реальным входным символам той же пары.

## Пример сеанса

Вход `transducer.json` задан, ввод пользователя — после `Enter an expression:`:

```text
The transducer translates arithmetic expressions into reverse polish notation (RPN).
An empty line or the 'exit' command finishes the session.
Enter an expression:
Translating: 5 + 3* 2
1) (q0, 5 + 3 * 2 ⊥, Z, λ) -> (q1, + 3 * 2 ⊥, Z, 5)
2) (q1, + 3 * 2 ⊥, Z, 5) -> (q2, 3 * 2 ⊥, Z, 5)
3) (q2, 3 * 2 ⊥, Z, 5) -> (q0, 3 * 2 ⊥, +Z, 5)
4) (q0, 3 * 2 ⊥, +Z, 5) -> (q1, * 2 ⊥, +Z, 5 3)
5) (q1, * 2 ⊥, +Z, 5 3) -> (q4, 2 ⊥, +Z, 5 3)
6) (q4, 2 ⊥, +Z, 5 3) -> (q0, 2 ⊥, *+Z, 5 3)
7) (q0, 2 ⊥, *+Z, 5 3) -> (q1, ⊥, *+Z, 5 3 2)
8) (q1, ⊥, *+Z, 5 3 2) -> (q7, λ, *+Z, 5 3 2)
9) (q7, λ, *+Z, 5 3 2) -> (q7, λ, +Z, 5 3 2 *)
10) (q7, λ, +Z, 5 3 2 *) -> (q7, λ, Z, 5 3 2 * +)
11) (q7, λ, Z, 5 3 2 * +) -> (q8, λ, Z, 5 3 2 * +)
RPN: 5 3 2 * +
ACCEPTED: the expression has been translated (final state 'q8').
Enter an expression:
Translating: (5 + 3)*2
1) (q0, ( 5 + 3 ) * 2 ⊥, Z, λ) -> (q0, 5 + 3 ) * 2 ⊥, (0Z, λ)
...
RPN: 5 3 + 2 *
ACCEPTED: the expression has been translated (final state 'q8').
Enter an expression:
Translating: 5 + * 3
Error: no transition is defined for the configuration (state 'q0', input '*', stack top '+') while reading the lexeme '*' (position 5); the expression violates the syntax of arithmetic expressions
Enter an expression:
exit
Bye!
```

При старте программа печатает сводку загруженного преобразователя (компоненты восьмёрки и всю
таблицу `δ`); каждый такт дополнительно логируется через `@Slf4j` (состояние, магазин, выходная
лента).

## Структура пакета

| Класс | Ответственность |
|-------|-----------------|
| `transducer.Transducer`, `transducer.Transition` | неизменяемая модель `P = (Q, V, Z, V', δ, q₀, z₀, F)` с таблицей переходов и проверками |
| `transducer.TransducerRunner` | движок: такты `(q, ax, zγ, y) ⊢ (r, x, αγ, yt)`, λ-переходы, принятие/отказ, лимит шагов |
| `transducer.TransducerParser` | загрузка конфигурации из json (Jackson) с полной валидацией |
| `transducer.Lexer` | лексический анализ строки (числа → `num`, пробелы — разделители, добавляется `⊥`) |
| `transducer.Configuration`, `Step`, `TranslationResult`, `Lexeme` | конфигурация `(q, x, α, y)`, такт, результат |
| `transducer.TransducerPrinter` | форматирование конфигураций, тактов и сводки (формат п. 2.5 задания) |
| `exception.TranslationException`, `exception.ConfigurationException` | диагностика с позицией символа / ошибкой конфигурации |
| `console.Console`, `console.SystemConsole` | ввод-вывод консоли (подменяется в тестах через Mockito) |
| `Main` | сеанс: загрузка конфигурации, цикл чтения строк, пошаговый вывод, обработка ошибок |
