# Лабораторная работа № 4 — перевод арифметических выражений в ОПЗ

Переводчик целых арифметических выражений (операции `+`, `-`, `*`, `/`, скобки) в обратную польскую
запись (ОПЗ) построен как последовательность «КС-грамматика → простая СУ-схема → детерминированный
МП-преобразователь → программа». Ниже — формальная часть (этапы 1 и 2); программная часть
(этап 3, формат json и пример сеанса) описана в `README.md`, конфигурация — в `transducer.json`.

## 1. Язык выражений и лексический анализ

Вход программы — строка с выражением. Программа выполняет лексический анализ и предъявляет
МП-преобразователю цепочку **лексем**:

- `num` — целое число: непустая последовательность цифр `0..9` (например `12`, `345`);
- `+`, `-`, `*`, `/` — операции;
- `(`, `)` — скобки;
- пробелы (и другие пробельные символы) — разделители лексем, в язык не входят и пропускаются;
- в конец цепочки добавляется концевой маркер `⊥` — он даёт преобразователю возможность обнаружить
  конец входа «настоящим» переходом и выполнить завершающие выталкивания из магазина.

Каждая лексема обрабатывается за один такт. Выходная лента преобразователя — цепочка лексем ОПЗ
**без разделителей** (например `532*+` для `5+3*2`); одиночные пробелы между лексемами вставляются
программой при выводе результата и при отображении конфигураций.

## 2. Этап 1. КС-грамматика

КС-грамматика входного языка:

```
G = (VN, VT, P, S),   VN = {S, E, T, F},   VT = {num, +, -, *, /, (, )}

P:
1. S → E
2. E → E + T
3. E → E - T
4. E → T
5. T → T * F
6. T → T / F
7. T → F
8. F → ( E )
9. F → num
```

- **Приоритет операций**: уровень `T` связывает `*`, `/`, уровень `E` — `+`, `-`; цепочка
  `E ⇒* T ⇒* F` требует, чтобы `T` разбирался как единое целое внутри `E`, поэтому
  `*` и `/` связывают аргументы сильнее, чем `+` и `-`.
- **Левоассоциативность** задана левой рекурсией: `E → E + T` разбирает `a + b + c` как
  `(a + b) + c`, а `T → T * F` разбирает `a * b / c` как `(a * b) / c`.
- Лексема `num` атомарна: грамматика описывает структуру выражений, а не посимвольную запись чисел.

## 3. Этап 1. Простая СУ-схема перевода в ОПЗ

Схема синтаксически управляемого перевода:

```
T = (VN, VT₁, VT₂, R, S),   VN = {S, E, T, F},
VT₁ = {num, +, -, *, /, (, )},   VT₂ = {num, +, -, *, /}

R (форма записи: входная часть, запятая, выходная часть):

S → E,           E
E → E + T,       E T +
E → E - T,       E T -
E → T,           T
T → T * F,       T F *
T → T / F,       T F /
T → F,           F
F → ( E ),       E
F → num,         num
```

- Схема **простая**: в каждом правиле вхождения нетерминалов во входной и выходной частях
  встречаются в одном и том же порядке — проверка по правилам:

  | Правило        | Нетерминалы в α | Нетерминалы в β | Порядок совпадает |
  |----------------|-----------------|-----------------|-------------------|
  | `S → E, E`     | E               | E               | да |
  | `E → E + T, E T +` | E, T        | E, T            | да |
  | `E → E - T, E T -` | E, T        | E, T            | да |
  | `E → T, T`     | T               | T               | да |
  | `T → T * F, T F *` | T, F        | T, F            | да |
  | `T → T / F, T F /` | T, F        | T, F            | да |
  | `T → F, F`     | F               | F               | да |
  | `F → ( E ), E` | E               | E               | да |
  | `F → num, num` | —               | —               | да (нет нетерминалов) |

- Значит, перевод `τ(T)` — **простой СУ-перевод**. Нетерминалы переписываются тождественно, а каждый
  оператор выдаётся в выходную часть **после** обоих своих операндов: правило `E → E + T` с выходом
  `E T +` добавляет `+` к выходу после `T`. Поэтому `τ(T)` — ОПЗ с приоритетом и
  левоассоциативностью исходной грамматики.
- **Выводимая пара** для `5 + 3 * 2` (левый вывод):

  ```
  (S, S) ⇒ (E, E) ⇒ (E + T, E T +) ⇒ (E + T * F, E T F * +) ⇒*
  ⇒* (num + num * num, num num num * +)
  ```

  при чтении `num` как 5, 3, 2 выходная часть даёт `5 3 2 * +`.
- В правилах схемы (и в выходной ленте преобразователя) разделительные пробелы не записаны:
  лексемы выхода разделяются одиночными пробелами при выводе строки результата
  (`num num num * +` → «5 3 2 * +»).

## 4. Этап 2. Детерминированный МП-преобразователь

### 4.1. Идея построения

Преобразователь — восходящая (LR) имитация простой СУ-схемы: вход разбирается в обратном порядке
правого вывода. Магазин хранит «ожидающие» операции — это входные символы `+`, `-`, `*`, `/` правил
`E → E + T`, `T → T * F` и т. п. Когда правая часть правила (нетерминал после операции) обработана,
операция выталкивается из магазина, и её символ выдаётся на выходную ленту — это и есть выполнение
выходной части правила (`E T +`). Выталкивание выполняется **λ-тактами** (без чтения входного
символа): после чтения операции или `)` может потребоваться несколько выталкиваний подряд.
Пробелы между лексемами ОПЗ на выходную ленту не выводятся — программа разделяет ими лексемы
при выводе.

### 4.2. Восьмёрка

```
P = (Q, V, Z, V', δ, q₀, z₀, F):

Q  = {q0, q1, q2, q3, q4, q5, q6, q7, q8}
V  = {num, +, -, *, /, (, ), ⊥}        (⊥ добавляется лексическим анализатором)
Z  = {Z, (, +, -, *, /}
V' = {num, +, -, *, /}
q₀ = q0
z₀ = Z
F  = {q8}
```

**Смысл состояний**

| Состояние | Смысл |
|-----------|-------|
| `q0` | начало работы; «ожидается операнд» (после `(` или операции) |
| `q1` | «операнд получен» (после `num` или `)`); допустимы `+ - * / ) ⊥` |
| `q2`, `q3` | λ-цикл выталкивания после чтения `+` / `-`: выталкивает операции с приоритетом ≥ прочитанной |
| `q4`, `q5` | λ-цикл выталкивания после чтения `*` / `/`: выталкивает только `*`, `/` |
| `q6` | λ-цикл после `)`: выталкивает операции с выдачей до маркера скобки и снимает маркер |
| `q7` | λ-цикл после `⊥`: завершающее выталкивание всех оставшихся операций |
| `q8` | заключительное состояние (принятие) |

**Смысл магазинных символов**

| Символ | Смысл |
|--------|-------|
| `Z` | начальный символ магазина (дно) |
| `+`, `-`, `*`, `/` | операции, ожидающие свою правую часть (вершина — самая внутренняя) |
| `(` | маркер «открытой скобки»: отделяет содержимое скобки от внешних операций |

Цепочка магазина записывается **с вершины слева**: `+Z` — вершина `+`, под ней `Z`.

**Выходной символ `num`** означает текст прочитанной лексемы-числа (эхо входа): правило с выходом
`num` переносит само число на выходную ленту.

### 4.3. Функция переходов δ (полная таблица, 80 правил)

Соглашения: `λ` в `push` — удалить символ с вершины; `push`, совпадающий с `z`, — не менять магазин;
`λ` в `output` — ничего не выдавать. Такт: если `δ(q, a, z) = (r, α, t)`, то
`(q, ax, zγ, y) ⊢ (r, x, αγ, yt)`.

**Состояние q0 — ожидание операнда**

| δ(q0, a, z) | = (r, α, t) |
|-------------|-------------|
| δ(q0, num, z), z ∈ {Z, (, +, -, *, /} | = (q1, z, num) — число переносится на выходную ленту |
| δ(q0, (, Z) | = (q0, (Z, λ) |
| δ(q0, (, () | = (q0, ((, λ) |
| δ(q0, (, z), z ∈ {+, -, *, /} | = (q0, (z, λ) — «`(`» вталкивается поверх ожидающих операций |

**Состояние q1 — операнд получен; чтение операции (правила 13–36: «прочитать и выталкивать»)**

| δ(q1, a, z) | = (r, α, t) |
|-------------|-------------|
| δ(q1, +, z), z ∈ {Z, (, +, -, *, /} | = (q2, z, λ) |
| δ(q1, -, z), z ∈ {Z, (, +, -, *, /} | = (q3, z, λ) |
| δ(q1, *, z), z ∈ {Z, (, +, -, *, /} | = (q4, z, λ) |
| δ(q1, /, z), z ∈ {Z, (, +, -, *, /} | = (q5, z, λ) |

(магазин не меняется; выталкивание выполнят λ-циклы состояний q2–q5)

**Состояние q1 — чтение `)` (правила 37–41)**

| δ(q1, ), z) | = (r, α, t) |
|-------------|-------------|
| δ(q1, ), z), z ∈ {+, -, *, /, (} | = (q6, z, λ) |

**Состояние q1 — конец входа ⊥ (правила 42–46)**

| δ(q1, ⊥, z) | = (r, α, t) |
|-------------|-------------|
| δ(q1, ⊥, Z) | = (q8, Z, λ) — выражение без ожидающих операций: принятие |
| δ(q1, ⊥, z), z ∈ {+, -, *, /} | = (q7, z, λ) — завершающее выталкивание |

**Состояние q2 — после `+`: выталкивать всё с приоритетом ≥ (левоассоциативность)**

| δ(q2, λ, z) | = (r, α, t) |
|-------------|-------------|
| δ(q2, λ, z), z ∈ {+, -, *, /} | = (q2, λ, z) — выталкивание с выдачей z на ленту |
| δ(q2, λ, Z) | = (q0, +Z, λ) — втолкнуть `+`, вернуться к ожиданию операнда |
| δ(q2, λ, () | = (q0, +(, λ) |

**Состояние q3 — после `-`**: те же 6 правил с заменой вталкиваемого символа на `-`
(δ(q3, λ, z), z ∈ {+, -, *, /} → (q3, λ, z); δ(q3, λ, Z) → (q0, -Z, λ); δ(q3, λ, () → (q0, -(, λ)).

**Состояние q4 — после `*`: выталкивать только `*` и `/`**

| δ(q4, λ, z) | = (r, α, t) |
|-------------|-------------|
| δ(q4, λ, z), z ∈ {*, /} | = (q4, λ, z) |
| δ(q4, λ, z), z ∈ {+, -, Z, (} | = (q0, *z, λ) — не выталкивать (низший приоритет), втолкнуть `*` сверху |

**Состояние q5 — после `/`**: те же 6 правил с заменой `*` на `/`.

**Состояние q6 — после `)`**

| δ(q6, λ, z) | = (r, α, t) |
|-------------|-------------|
| δ(q6, λ, z), z ∈ {+, -, *, /} | = (q6, λ, z) — выталкивать операции до маркера скобки |
| δ(q6, λ, () | = (q1, λ, λ) — снять маркер скобки; выражение в скобках = операнд |

**Состояние q7 — завершающее выталкивание**

| δ(q7, λ, z) | = (r, α, t) |
|-------------|-------------|
| δ(q7, λ, z), z ∈ {+, -, *, /} | = (q7, λ, z) |
| δ(q7, λ, Z) | = (q8, Z, λ) — принятие |

**Состояние q8** — заключительное, переходов не имеет.

Итого: 12 + 34 + 6·4 + 5 + 5 = **80 правил**.

**Детерминированность.** Для каждой тройки `(q, a, z)` определено не более одного правила; λ-правила
существуют только в состояниях `q2`–`q7`, у которых нет переходов по реальным входным символам,
поэтому конфликтов «λ против реального символа» для пары `(q, z)` нет.

**Принятие.** Цепочка лексем `x` принимается, если `(q0, x, Z, λ) ⊢* (q8, λ, α, y)` для некоторого
`α ∈ Z*`; цепочка лексем `y` — перевод `x` (ОПЗ без разделителей; при выводе лексемы разделяются
пробелами). Любой другой исход (нет правила для текущей конфигурации, вход исчерпан в
незаключительном состоянии) — отказ с диагностикой позиции.

### 4.4. Разбор контрольного примера `5 + 3* 2`

Лексический анализ: `5 + 3* 2` → цепочка лексем `num + num * num ⊥` (пробелы пропущены,
`⊥` добавлен). Последовательность конфигураций (в точности совпадает с пошаговым выводом
программы; выходная лента отображается с разделителями между лексемами):

```
1) (q0, 5 + 3 * 2 ⊥, Z, λ) -> (q1, + 3 * 2 ⊥, Z, 5)
2) (q1, + 3 * 2 ⊥, Z, 5) -> (q2, 3 * 2 ⊥, Z, 5)
3) (q2, 3 * 2 ⊥, Z, 5) -> (q0, 3 * 2 ⊥, +Z, 5)
4) (q0, 3 * 2 ⊥, +Z, 5) -> (q1, * 2 ⊥, +Z, 5 3)
5) (q1, * 2 ⊥, +Z, 5 3) -> (q4, 2 ⊥, +Z, 5 3)
6) (q4, 2 ⊥, +Z, 5 3) -> (q0, 2 ⊥, *+Z, 5 3)
7) (q0, 2 ⊥, *+Z, 5 3) -> (q1, ⊥, *+Z, 5 3 2)
8) (q1, ⊥, *+Z, 5 3 2) -> (q7, λ, *+Z, 5 3 2)
9) (q7, λ, *+Z, 5 3 2) -> (q7, λ, +Z, 5 3 2 *)
10) (q7, λ, +Z, 5 3 2 *) -> (q7, λ, Z, 5 3 2 * +)
11) (q7, λ, Z, 5 3 2 * +) -> (q8, λ, Z, 5 3 2 * +)
```

Выход `y` — цепочка лексем `5 3 2 * +`. Комментарий к ключевым тактам:

- такты 3, 6 — λ-такты: после чтения операции конфигурация «дочитывает» решения по стеку без чтения
  входа (такт 3 вталкивает `+`, такт 6 вталкивает `*` поверх `+`, поскольку приоритет `*` выше);
- такт 5 — чтение `*` в состоянии `q4`: выталкивание отложено до λ-такта 6, чтобы `+` остался в
  магазине (приоритет `*` старше);
- такты 9, 10 — завершающие выталкивания `*` и `+` по `⊥`;
- такт 11 — переход в заключительное состояние `q8` (принятие, магазин непуст — это допустимо).

Проверка: `5 3 2 * +` = `5 + (3 * 2)` = 11 — перевод совпадает с ОПЗ выражения `5 + 3* 2`.
